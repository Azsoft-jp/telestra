# 00 / 設計再検討・決定記録

更新: 2026-10-29。対象: 個人〜小規模運用を最初の実装範囲とし、将来的なエンタープライズ要件を満たすための境界と運用条件を定義する。「大規模事業者向け認証済み」ではない。

## 目指す利用体験

- まず画面を開き、チューナーを接続するとEPGが見られる。番組選択→視聴・予約が少ない操作で完了する。
- 視聴中の字幕・音声切替、録画の検索、事後エンコード、端末保存が分かりやすい。
- 失敗時は「何が起き、何が保存済みで、次にできること」が画面に表示される。
- ユーザーは高度なStorage/Encode/DR設定を最初に求められない。初期設定は安全な推奨値を適用。

## 過去のアイデアからの重要な訂正

| 以前の単純化 | 修正した判断 |
| --- | --- |
| TSを数秒で切ればHLS配信できる | 原本TSのバイト保持チャンクとHLSの再生セグメントは異なる。Packagerが必要 |
| Direct fallbackとして生TSをブラウザに流す | 地デジMPEG-2 Videoは通常ブラウザ再生不可。端末能力判定、なければ変換待ち |
| 字幕はWebVTTへ変換すると必ず情報を失う | ARIBを特殊cueで保持するWebVTT方式もある。汎用テキスト字幕と区別する |
| TunerNodeに独自EPGパーサーが必要 | Mirakurun/mirakcのPrograms等の既存APIを優先し、差分同期だけ担当 |
| CloudflareのWSで映像も常時転送 | WSは制御。映像は署名付き/対象限定HTTPS等のデータ面を利用 |
| リース切れで完全に二重録画を防止 | ネットワーク分断では不可能。attempt別原本を保持し、正規公開を一つに収束 |
| D1のread replicaで書込Active-Active | read replicaは非同期の読取複製。書込はprimaryに集約 |
| R2にMultipartの途中が見える | 完了まで通常オブジェクトとして不可視。追っかけ再生は確定済みチャンク・別プレイリスト |
| フロントを二重化すれば全体のDR | 二重化するのは静的UI。API・認証・データは別途DRが必要 |
| PWAで端末録画が必ず完走する | OSがバックグラウンド処理やデータを制限し得る。前景・再開可能DLを標準化 |
| すべての機能を一度に移植 | 契約とMedia vertical slice、EPG、UX、DRの順に段階的に開発 |

## 採用するADR（決定）

| ID | 決定 | 理由・代償 |
| --- | --- | --- |
| ADR-001 | CF-first、公開Contractはプロバイダー非依存 | 早期に完成させつつ可搬性確保。全クラウドの同等性は約束しない |
| ADR-002 | Lightweight TunerNode / Go | 小メモリ・単一バイナリ。既存Mirakurun/mirakcに依存 |
| ADR-003 | 原本TSをimmutable chunk+manifestで保存 | 途中転送/復旧/改ざん検知に適する。単一TSファイル形式は書き出しで再構成 |
| ADR-004 | 専用EncodeNode、リアルタイム優先予約枠 | TunerNodeを軽量化。ライブ切替には途切れが起こり得る |
| ADR-005 | メタデータ/予約intentはDurable Storeを正本 | 一時接続状態はDOで管理、復旧時再計算 |
| ADR-006 | フロント同一ビルドdual-static、予備URLは別origin | 低運用負荷。PWA保存・Cookieの共有不可 |
| ADR-007 | PWAオフラインライブラリとファイル書出を区別 | UXとOS差異を明示。背景DL保証なし |
| ADR-008 | WebSocketは制御だけ、Shell機能なし | 権限最少化、データ面の帯域を分離 |
| ADR-009 | IaCにTerraform/OpenTofu、WorkerリリースにWrangler | UIとインフラの更新頻度差を吸収。Bindingの設定責任を固定 |
| ADR-010 | 自動削除は成功検証と明示的ポリシー後 | 消失リスクを可視化 |

## 実装の優先順位

- **P0 — 動作・安全の土台**: Mock、API契約、Node接続、録画原本、再試行、字幕保持モデル、EPG、事後変換の一本検証。
- **P1 — 日常に使える**: Live、字幕/音声切替、録画検索、予約、PWA前景保存、レスポンシブ、状態表示。
- **P2 — 運用**: 2本のEncodeNode、Front dual-static、監視、DR演習、Storage tiering。
- **P3 — 高度機能**: 他クラウドControl Plane、複数家庭/テナント、配信高可用性、データ放送、実況/SNS、より広い端末対応。

## 明示的な非目標

- KonomiTV APIへの完全なdrop-in互換。
- 現時点でのデータ放送・字幕・DRM・外部プレイヤーの完全再現保証。
- 視聴/録画サービスの第三者公開や地域制限解除。
- 単一家庭チューナーのみでの物理ノード障害耐性。
- 0Bのローカルバッファで通信断に無制限対応。
- 前景外でも終了しないPWA録画・永久保持・他origin間のオフラインデータ共有。

## 未決定・検証待ち

1. 最初の実機（Mirakurunバージョン、mirakc、チューナー台数、OS、回線上り）と視聴端末を指定。
2. ARIBの保持形式（生データ、特殊WebVTT、ID3 sidecar等）をgolden fixtureで比較し固定。
3. Encode出力/対応コーデックは端末実測で決定。AV1/HEVCを最初から必須にしない。
4. 外部IdP、第二静的ホスト、第二Storageの選定は予算・地域条件確認後。
5. 録画TSの再配信、コンテンツ保管・ダウンロードについて権利・利用規約の確認。

文献・検証根拠は`docs/10-references.md`。未実測の目標値は`docs/05-reliability.md`に仮目標と明記。
