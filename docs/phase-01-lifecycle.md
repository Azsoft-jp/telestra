# 接続中の資格更新と再接続

2026年10月29日のPhase 01追加実装を記録する。[ADR-020](architecture/decisions/ADR-020-go-credential-lifecycle.md)に従い、Lifecycleが参加済みのGo ProvisionerとWSS Clientを調停する。本番資源、既存の秘密値、実チューナー・実録画は使用しない。Phase 01全体は未完了である。

## 変更点

既定の更新時刻は資格の期限30秒前である。旧接続と受信goroutineを回収してからrotateを一度だけ呼び、新しい資格でWSSへ接続する。Nodeの能力と命令履歴を維持し、接続世代はWorkerで進める。正常な更新時には更新中・更新済みを通知し、Agent全体の停止と混同しない。通知は状態、試行数、更新数、資格世代だけで、資格や鍵を含まない。

同じLifecycleの並行Runを拒否し、HTTPとWSSのorigin、登録端末、履歴を同じ構成へ拘束する。Run中にProvisionerを別の更新処理と共有しない。通信障害では既存Runnerを使い、更新後も消費した再試行枠とbackoffの幅を引き継ぐ。予定した更新は正常な保守操作として継続するが、失敗を無制限に再試行しない。

旧接続を閉じられない、署名・契約・認証が不正、更新の結果が不明な場合は停止する。予定したContextの中断に他の失敗が含まれていれば、それも停止として扱う。更新は旧資格の期限を越えて待たず、更新結果不明では再送しない。管理者による新しい参加コードでの復旧は[参加・更新の記録](phase-01-provisioning.md)に従う。

## 確認方法と試験範囲

```sh
go test -race ./nodes/tuner/control -run '^TestLifecycle' -count=1 -timeout=25s
npm run control:check
npm run check
```

Goの単体試験では短い合成資格を使い、旧接続終了→更新→再接続の順序、結果不明、解放失敗、期限が延びない応答、再試行枠・backoffの引き継ぎ、恒久エラー、中断、並行実行、originの不整合を確認する。鍵と資格はメモリ内で作り、エラー本文や証跡へ出さない。

WorkerとのNODE-02相互試験は、寿命300秒の資格の更新時刻だけを期限290秒前に指定する。約10秒後に旧接続を閉じて更新し、新しい資格と接続世代でhelloが通ること、予約台帳の保持、Node失効後に追加更新せず停止することを確認する。資格の寿命や署名検証を短絡しない。既定の更新間隔を長時間運転した試験ではない。

## 実行結果

macOS arm64、Go 1.26.10、Node.js 24.22.1で確認した。

| コマンド・対象 | 結果と範囲 |
| --- | --- |
| npm run check | 終了コード0。既存16試験、Phase 01の24試験、Go全体のrace、型・Schema生成差分・静的検査 |
| GoのLifecycle対象試験 | 正常更新9回が障害枠を消費しないことを確認。予定時刻前の解放失敗も含む10試験を追加 |
| NODE-02の更新相互試験 | 約10秒で更新・新世代接続・予約台帳・失効後停止を確認。外向きfetchは0回 |
| govulncheck ./... | 検出0件。Go 1.26.10で確認 |
| Gitleaks作業ツリー | 検出0件。値をredactし、秘密の本文を出力しない |
| Linux arm64 | 試験バイナリのコンパイルに成功。arm64での実行は未実施 |

追加試験で、資格更新後にbackoffの幅が初期化される問題を再現し、消費した失敗回数に応じて幅も引き継ぐよう修正した。空のUnwrapを返す接続解放エラーを予定中断と誤認する問題も再現した。最初の試験は誤った継続により10秒でtimeoutしたため、予期しない再接続を直接拒否するfixtureへ直して失敗を確認し、分類を修正した。修正後の全検査で合格を確認し、失敗した実行を成功として扱っていない。

証跡はartifacts/phase00-results.json、go-results.json、phase01-results.jsonと実行ログへ保存する。GoとWorkerの資格・鍵のIPCは証跡へ保存しない。日本語コメントと文書はyomiyasuで検査し、差分の情報追加が実行結果と一致することを確認する。

初回PRのCIは全項目が成功したが、最終確認で予定時刻前の解放失敗を既存Runnerが再試行する経路を見つけた。追加試験で失敗を再現し、ErrSessionCloseを付けて恒久失敗として停止するよう修正した。予定時刻の前後にかかわらず、接続を回収できたか不明な状態で次へ進めない。

この修正で、解放失敗後にもbackoffを前提としていた既存試験が失敗した。正常に解放した後のbackoff中断と、解放失敗時の即停止を別の試験へ分け、両方の条件を維持する。

## 未確認・リスク・次の入力

鍵・資格・最後の確認世代はメモリ内で、再起動後の復旧は未実装である。既定間隔の長時間運転、実環境WSS、時刻ずれ、実EncodeNodeは未検証である。接続を閉じてから更新するため短い制御の空白がある。確定予約の実行、資格世代をまたぐ未ACK処理、実録画への影響は、この試験だけでは保証しない。

次は対象OSと鍵の保管・配布・復旧権限を具体化し、再起動後の資格と確認世代を照合する。実サービスへの接続や本番資格の取得・配布は別の手順と明示的な承認を必要とする。設計で未決定の本番方式を、このローカル実装から自動的に確定しない。
