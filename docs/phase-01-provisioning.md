# Goの参加・資格更新と復旧

2026年10月29日のPhase 01追加実装を記録する。GoのProvisionerから既存Workerのjoin/rotateを呼び、更新後の短命資格でWSSへ接続する。[ADR-019](architecture/decisions/ADR-019-go-node-provisioning.md)で、応答が失われた場合の扱いを具体化した。Phase 01全体は未完了である。

## 変更と信頼境界

資格応答をCredentialResponseのSchemaへ追加し、WorkerとGoの両方で検証する。応答のNode・役割・世代・期限と署名済みclaimsが一致しなければ受け付けない。rotateは直前の世代から一つだけ進むことを要求し、再参加でも最後に確認した世代以下の応答を拒否する。

接続先は構成済みのHTTPS originに限定し、操作はjoin/rotateだけとする。TLS証明書を検証し、Proxy環境変数、リダイレクト、Cookie、Origin、圧縮を使用しない。要求は8KiB、応答は16KiB、応答ヘッダーは16KiB、操作は10秒までとする。応答本文の実サイズ、JSONの重複キー、未知項目、文字コード、署名も検査する。資格、鍵、参加コード、相手の自由文をログへ出さない。

送信開始前の入力不正・中断では現在資格を保持する。送信開始後はProvisionerから旧資格を返す処理を止め、成功した新資格だけを返す。通信障害、HTTPエラー、不正応答、中断では結果不明として停止し、同じ変更を自動再送しない。Runnerも結果不明を再試行しない。期限が切れた資格は参加待ちへ戻す。

復旧には管理者が新しい参加コードを発行し、同じ登録端末鍵でjoinする。失効したNodeはこの方法でも復旧できない。秘密値を問い合わせやIssueへ貼らず、状態とエラー分類だけで調査する。

## 再現方法と確認範囲

Go 1.26.10とNode.js 24の環境で、[既存のローカル実行手順](phase-01-runbook.md)を使う。

```sh
go test -race ./nodes/tuner/control -run '^TestProvision' -count=1 -timeout=20s
npm run control:check
npm run check
```

Goのfixtureコマンドは試験専用で、本番のNode起動コマンドではない。管理者の公開鍵登録・参加コード発行だけをTypeScript側で行い、join/rotateの署名とHTTPS通信はGoで行う。新資格でWSSへ接続してhelloを送り、失効後は停止する。資格と鍵はメモリとIPCだけで扱い、実チューナー・実IdP・本番Cloudflareを使用しない。

## 検証結果

macOS arm64、Go 1.26.10、Node.js 24.22.1でnpm run checkが終了コード0となった。Phase 00等の16試験、Phase 01の23試験、Goのrace付き全試験、Schema生成差分、型、書式、日本語コメント、Go vet、error戻り値、公開情報・ローカルリンク検査を含む。

追加のGo試験では、join/rotateの端末署名、TLS・ヘッダー、結果不明後の再参加、同時更新、送信前後の中断、期限切れ、世代の巻き戻りと飛び越し、別家庭・環境・用途、未知項目、過大応答、応答の形式、リダイレクト拒否を確認した。整数の1.0・指数表記を誤って拒否する問題もテストで再現し、Schemaで整数と確認した値を数値として照合するよう修正した。修正後の対象試験と静的検査は再実行して成功した。

最初のWorker相互試験は、初期世代の固定値を誤って期待して失敗した。joinの応答世代からrotateが一つ進むことを確認するよう直した。中断試験のHTTP fixtureも、接続終了の通知を待って解放できず停止した。試験ハンドラーを明示的に解放するよう直し、20秒の試験上限内で再確認した。失敗を成功の記録へ読み替えない。

Gitleaksの作業ツリー検査とgovulncheckは検出0だった。履歴とGitHub Actionsは公開PRの検査でも確認する。証跡はartifactsのPhase別レポートと実行ログへ保存し、秘密値を含むIPCを保存しない。日本語コメントと文書にはyomiyasuの静的検査と差分確認を適用した。

## 未実装と次の作業

資格と最後の確認世代はメモリ内で保持する。本番の鍵保管・配布、再起動をまたぐ資格と世代の復旧、常駐中の期限前更新とWSS接続の調停、実EncodeNode、実環境WSSは未実装または未検証である。現在資格を受け取った既存Clientを自動更新する機能もまだない。呼出元が取得済みの資格のコピーをProvisionerから回収することはできず、既存WSSの終了は呼出元が扱う必要がある。期限後の継続運用や無人復旧を保証しない。

次は期限前更新、既存接続の終了、更新後の再接続を一つの有限な状態機械へ結ぶ。更新結果不明時は再参加が必要という境界を維持する。永続的な鍵保管方式を決める前に、対象OS、鍵保管先、復旧権限を確認する。実録画・媒体処理・PWA・DRは対象外のままである。
