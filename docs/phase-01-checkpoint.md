# 資格変更の確認情報と再読込

2026年10月29日のPhase 01追加実装を記録する。[ADR-021](architecture/decisions/ADR-021-node-credential-checkpoint.md)に従い、秘密値を保存しない確認情報をGoの命令履歴へ追加する。Phase 01全体は未完了である。

## 変更と保存内容

履歴v2は、従来の命令・応答・接続世代に加え、端末と信頼先の束縛hash、最後に確認した資格世代とhash、操作ID、pending/readyを保存する。秘密鍵、資格の本文、参加コード、端末証明の本文を保存しない。資格hashをBearerとして使用することもできない。

ProvisionConfigのJournalを必須とし、Lifecycleも同じJournalを使う。join/rotateの開始をsyncしてからHTTPを送り、応答の検証と確定保存に成功してから資格を返す。途中状態が残ると旧資格を返さず、再参加を要求する。異なる操作IDの遅れた応答で新しい操作を上書きしない。保存後の中断は、送信前でも結果不明として扱う。

再読込後はneeds-restoreを返し、RestoreCredentialへ外部からメモリで渡した資格を照合する。署名・期限・用途・家庭・環境・役割に加え、最後の世代とhashが一致しなければ復元しない。構築済みの旧Clientからの再接続も、HTTPを送る前に拒否する。実際の失効・現在世代は接続先のD1でも確認する。

## 移行と再現方法

v1履歴は命令・応答・接続世代を保持して読み込む。記録のなかった鍵を推測して接続することはせず、明示的なjoinで束縛を確定する。次の保存はv2で、旧バイナリによるv2の読込は非対応である。履歴を削除してエラーを消す手順は提供しない。

```sh
go test -race ./nodes/tuner/control -run '^TestEnrollment' -count=1 -timeout=25s
npm run control:check
npm run check
```

Goの試験は、最後の資格と世代、別鍵・接続先・発行者、旧Client、保存失敗、操作の競合、v1移行と再送応答、破損・未知項目・nullの拒否を扱う。子プロセスを開始記録の保存直後に終了し、deferに依存しないOSロックの解放とpending保持も確認する。秘密値はメモリにだけ保持し、子プロセスの環境変数へは非秘密の試験パスと状態だけを渡す。

Worker相互試験は、同じGoプロセスで履歴・Provisioner・Clientを作り直す。秘密値はメモリに保持し、履歴だけを開き直して資格を復元する。新たなjoin/rotateを発生させず、接続世代1から2へ再開し、失効時は停止する。これは本番KeyProviderや、Workerを伴うOSプロセスの完全な再起動を検証したものではない。

## 実行結果

macOS arm64、Go 1.26.10、Node.js 24.22.1で確認した。

| コマンド・対象 | 結果と範囲 |
| --- | --- |
| npm run check | 終了コード0。既存16試験、Phase 01の25試験、Go全体のrace、型・Schema生成差分・静的検査 |
| Goの確認情報の試験 | 復元・途中終了・保存失敗・移行・不正入力の対象試験をrace付きで実行し成功 |
| NODE-02の再初期化相互試験 | 同じプロセス内で資格を再照合し、接続世代1→2、resumeの旧世代1、失効後停止を確認。外向きfetchは0回 |
| govulncheck ./... | 検出0件。Go 1.26.10で確認 |
| Gitleaks作業ツリー | 検出0件。値はredactし、秘密の本文を出力しない |
| Linux arm64 | 試験バイナリのコンパイル成功。arm64での実行は未実施 |

資格世代とlegacyのnullがencoding/jsonでゼロ値へ変換され、状態として受け入れられる問題を追加試験で再現した。保存データの実際の型も検査して拒否するよう修正し、対象試験と全検査を再実行して成功した。既存の接続試験は登録済みの試験資格を明示的に確定し、Lifecycleの短い資格も応答から受け取るよう変更した。記録を迂回して資格を差し替えるfixtureにはしない。

証跡はartifactsのPhase別レポートと実行ログへ保存する。日本語コメントと文書はyomiyasuの静的検査と差分確認を行い、追加した結果が実行した試験と一致するか確認する。

## 未実装・リスク・次の入力

本番の鍵・資格の保管と供給Provider、失効・更新とその保存順序、実環境WSS、実EncodeNode、実ディスクの電源断・停止は未実装または未検証である。hashはファイル全体の改ざんや古いsnapshotへの復元を防ぐ認証子ではない。D1の世代照合を省略せず、端末だけで完全な耐rollbackを保証しない。

対象OS、鍵の保管方式と供給経路、復旧権限を次の入力とする。現在のRestoreCredentialはメモリで渡された値を検証する入口であり、秘密値の取得・保存・配布を実行しない。本番の方式と権限を、この実装だけで確定しない。
