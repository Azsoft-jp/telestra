# ADR-021 資格変更の確認情報と履歴v2

Phase 01のローカル検証向けに採用する。本番の鍵保管方式は未決定のまま維持する。秘密鍵、資格の本文、参加コードをファイルへ保存しない。

## 理由と決定

[ADR-019](ADR-019-go-node-provisioning.md)のProvisionerは、再起動すると最後に確認した資格世代と更新途中の状態を失う。既存の小さな命令履歴へ、接続先・発行者・端末・公開鍵の束縛hash、確認済み世代、資格のhash、操作ID、pending/readyを追加する。hashは元の資格として認証に使えない確認情報であり、秘密の復元手段ではない。

更新の開始記録をsyncしてからHTTPを送り、署名・境界・世代を検証した応答をsyncしてから新資格を返す。保存失敗を空の状態や成功へ読み替えない。操作IDが一致しない遅れた応答は確定しない。pendingが残った場合は、旧資格の復元・新しい命令・接続世代の進行を拒否し、管理者による再参加を要求する。

ADR-019の送信直前の境界を、永続的な開始記録へ具体化する。開始記録の保存後は、HTTP送信前に中断しても保守的に結果不明として隔離する。未送信であることを確定して取り消す処理はまだ設けない。保存前の入力不正・中断では操作を開始しない。

再読込後の資格は外部からメモリへ渡し、署名・用途・期限・世代・hashを照合して復元する。鍵や資格を取り出すProvider自体はこの変更に含めない。Clientも同じ束縛と資格を確認し、構築済みの古いClientからの再接続を拒否する。初回の直接設定は、履歴のない新規状態に限る。

## 互換性とトレードオフ

保存形式をv2とする。v1の命令・応答・接続世代を保持して読み込むが、記録されていない鍵は推測しない。v1履歴では明示的なjoinを経て束縛を確定する。次の保存でv2となり、旧バイナリへ戻してv2を読み込む手順は提供しない。wire形式、JWT用途、Schema IDは変更しない。

別ファイルへ保存する案は、命令履歴との排他・確定順序が増えるため採用しない。既存の0700/0600、OSロック、一時ファイル・sync・renameを使う。Tokenや秘密鍵の平文保存、固定の暗号鍵を同梱する案は採用しない。本番では外部の安全な保管方式と結ぶ必要がある。

この確認情報はローカル管理者による改ざん、履歴ファイル全体の古いsnapshotへの復元を防ぐ信頼根ではない。サーバーの失効・世代照合は引き続き必要で、端末内だけの耐rollbackやTPM相当の保証とは扱わない。保存I/Oを強制的に打ち切る機能もなく、実ディスクの停止や電源断は別の検証を要する。

## 試験・質問候補・見直し条件

NODE-02/SEC-02の範囲で、最後の資格だけの復元、別鍵・接続先・発行者、途中終了、保存失敗、旧Client、v1移行、破損・null・未知項目を検証する。Worker相互試験の履歴再初期化と、別のGo試験での子プロセス途中終了を区別して報告する。

本番の鍵・資格を扱う前に、対象OS、KeyProvider、秘密値の供給経路、復旧主体、保管資格の失効・更新順序を確認する。確認情報の保持・バックアップ・復旧方法、保存I/O停止時の扱いも再検討する。これらをローカルfixtureの成功から自動決定しない。
