# ADR-015 Goの制御契約と永続履歴

資格確認情報とv1→v2の移行は[ADR-021](ADR-021-node-credential-checkpoint.md)で追加した。以下の初期保存項目の記述と区別し、秘密値を保存しない原則は維持する。

状態はPhase 01のローカル検証向け採用。GoのWSS Transportとの統合は[ADR-016](ADR-016-go-wss-transport.md)で追跡する。実チューナー、実録画、本番の鍵運用は未実装・未検証のまま残す。

## 契約と署名

JSON Schemaを契約の入力として維持する。controlと参照先のcapture-permitをGoへ生成して埋め込み、実行時に外部参照を取得しない。Goは使用中の制約だけを検証する。未対応のキーワード、type、format、pattern、$refの兄弟制約が追加された場合は生成を止める。汎用のDraft 2020-12準拠や、全入力でのAjvとの同等性は保証しない。

GoのEd25519は標準ライブラリを使用する。鍵の選択は設定済みのkidと公開鍵に限り、EdDSA以外の署名、別用途のToken、ヘッダーの追加項目を拒否する。受信したJWSのバイト列で署名を確認してから本文を解析する。家庭・環境・Node・資格世代・接続世代・方向・期限を照合する。接続通知は保存済み世代より新しい場合だけ受け付ける。

Go側はサイズ、JSONの深さ、重複キー、不正UTF-8も検査する。Envelopeの日時は秒精度を要求し、うるう秒や秒未満の日時を受け付けない。JSON Schemaの文字列形式に通っても、実行時に数値化できない日時は拒否する。JavaScriptとGoの正規表現の違いを無理に吸収せず、確認済みパターンだけを生成対象とする。

## 小さな永続履歴

TunerNodeへDBを追加せず、専用ディレクトリの小さなJSONファイルへ接続世代と命令履歴を保存する。保存するのは家庭・環境・Node・役割、命令ID、本文のhash、処理状態、応答だけである。Token、秘密鍵、媒体バイト、原本の代替データは保存しない。

処理前のpendingをsyncしてからハンドラーを呼び、結果を確定した後にdoneを保存する。同じ命令IDと本文の再送には保存済み応答を返す。本文が違えば拒否する。処理途中で停止し、pendingだけが残った場合は結果不明として自動再実行しない。新しいattemptを作る録画復旧の規則はPhase 02で別に定義する。

書込は一時ファイル、ファイルsync、rename、ディレクトリsyncの順で行う。失敗を検出した履歴インスタンスは以後の処理を停止する。破損した履歴を空として読み替えない。結果保存の失敗後も、命令が未実行だったとは推定しない。

履歴は最大128件・64KiBとし、上限では新しい命令を拒否する。完了済みIDを自動削除する処理はまだ設けない。長時間運用に必要な保持期間、圧縮、照合、結果不明からの復旧手順は未決定である。

## OSと排他

専用ディレクトリは0700、履歴とロックファイルは0600を要求する。既存の広い権限を自動で変更しない。LinuxとmacOSではOSの排他ロックを保持する。異常終了時はOSがロックを解放するため、残ったロックファイルを削除して復旧する必要はない。symlinkをたどらず、通常ファイル以外を拒否する。他OSで排他を省略するfallbackは設けない。

## 試験と残作業

GoとWorkerの相互試験では、試験鍵とTokenを標準入出力のIPCで受け渡す。値をログや検証証跡へ保存しない。Goのfixtureコマンドは署名・検証だけを扱い、通信、Shell、任意パス操作を実装しない。Nodeの応答はnot implementedであり、録画成功を装わない。

履歴の並行再送、再読込、別家庭、破損、symlink、保存失敗、子プロセスの異常終了を試験する。これらは実ディスクの電源断や破損を証明しない。公開WSSライブラリの参照・取得はユーザーが承認し、WSSと受信ループを接続した。ローカルTLSでの再接続と、検証・履歴を通る経路はADR-016の範囲で確認する。
