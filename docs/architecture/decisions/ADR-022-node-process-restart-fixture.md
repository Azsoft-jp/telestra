# ADR-022 別プロセスによる資格復元の試験

Phase 01のローカル試験に採用する。本番KeyProviderの選定は[ADR-021](ADR-021-node-credential-checkpoint.md)の未決定事項として残す。

## 理由と決定

従来のWorker相互試験は、同じGoプロセスで履歴を開き直していた。OSがプロセスを終了した後のロック解放と、別プロセスでの資格復元を、Workerの現在世代と組み合わせて確かめる必要がある。

親のNode.js試験が合成鍵と資格をメモリへ保持する。Goの試験コマンドは、参加・更新で検証した資格だけをFD3の専用Unix socketへ返す。親も署名・用途・端末・世代を照合する。通知はサイズを制限し、Goの書込期限を5秒とする。通常ファイル、FIFO、端末、TCP socketへの書出しは拒否する。進捗のstdoutには状態と件数だけを許可する。

プロセス間で共有するのは非秘密の履歴である。親が作った0700の一時領域を、32桁の小文字hex IDから固定の接頭辞で参照する。任意パスを入力させず、symlink、通常ファイル、権限の異なる領域を拒否する。親が試験終了時に削除する。公開アプリのAPIには追加しない。

更新の途中終了は、join/rotateだけを中継するloopback TLSの障害注入サーバーで再現する。実際のローカルWorkerが世代を確定した後、応答をGoへ渡さず、親がSIGKILLを送る。別のGoプロセスはpending履歴と旧資格からの復元を拒否する。自動再参加やHTTPの自動再送で結果不明を解消しない。

## 代替案とトレードオフ

同一プロセス内の再初期化は速いが、今回のOS境界を検証しない。資格を一時ファイルや環境変数へ保存する案は、秘密値の保管方式を先に決めてしまい、ログや成果物へ残す経路も増えるため採用しない。親メモリと専用IPCは試験の再現性を得られるが、親プロセス自体の終了から秘密値を復元できない。

試験コマンドと障害注入コードが増えるため、既存のWSS試験と共通の起動・出力検証を使う。失敗を隠すcleanupは行わず、終了状態と接続の回収を確認する。Wire契約、Journal v2、本体のProvisionerは変更しない。

## 試験・見直し条件・質問候補

NODE-02で別のGoプロセスへの復元と接続世代1→2を検証する。旧資格と別鍵は接続前に拒否する。SEC-02でWorker更新後のSIGKILL、pending保持、OSロック解放、旧資格の復元拒否、追加HTTPと接続世代の進行がないことを確かめる。共有領域と資格出力先の拒否条件はGoのrace付き試験で確認する。

本番KeyProvider、端末OS、秘密値の保管・更新・復旧主体が決まった際に見直す。IPCの成功を、電源断、ディスク停止、実IdP、実クラウド、OS再起動、本番の秘密値復元の保証として扱わない。ローカル管理者による改ざんや履歴全体の巻き戻りも別の問題として残す。
