# ADR-027 Node認可世代のD1保存

状態はローカル実装向けの採用。[ADR-026](ADR-026-capture-permit-v2-proposal.md)で選択した世代分離を、制御側の永続状態へ適用する。署名付きpolicyの配信・Nodeキャッシュ・実録画は、この決定だけで有効にしない。

## 理由と決定

従来のnodesにはcredential_versionとsession_epochだけがあった。v2の検証器へ渡すauthorizationEpochを資格世代から推測すると、通常rotateでも録画許可が変わる。Nodeごとの認可世代authorization_epochをD1の同じrowへ追加し、家庭・環境・Nodeの主キーで分離する。

新規登録と既存DBの移行では1から開始する。過去の認可履歴は再構成しない。既存の製品APIはv2 Permitやpolicyを発行していないため、移行時に旧v2キャッシュを有効と認定する手順も設けない。

明示的なjoinは、新規参加でも再参加でもCredential世代と認可世代を進める。通常rotateはCredential世代だけを進める。失効は状態と両世代を一つのUPDATEで確定する。失効の再送では世代を進めず、失効したNodeへの再参加や同じIDでの鍵・Roleの上書きは引き続き拒否する。

世代の上限は安全な整数の最大値9007199254740991とする。join/rotateで必要な世代を進められない場合は409で拒否し、参加権利を消費しない。上限でも失効そのものは拒否しない。該当する世代値を上限に保ってstatusをrevokedへ確定し、0への巻き戻しやNode IDの再利用を行わない。失効判定では世代の一致だけでなく状態も必須となる。

## 保存と障害

[0002の追加移行](../../../apps/control/migrations/0002-authorization-epoch.sql)を0001の後へ適用する。型と範囲はDB制約でも検査する。既存の資格・公開鍵・接続世代・予約・録画台帳を置き換えない。未移行DBや不正な認可世代を、既定値1へ補って認証する処理は設けない。

joinの状態・世代更新と参加権利の消費は、従来と同じD1 batchへまとめる。更新失敗で参加権利だけを失わせない。書込に失敗した失効を成功表示しない。状態の確定後に監査・接続終了の処理やHTTP応答が失敗した場合は、再送時に現在の失効状態へ照合する。通信の成功と認可の永続化を混同しない。

## 代替案とトレードオフ

Credential世代をそのまま使う案は列を増やさずに済むが、ユーザーが選んだ分離と矛盾する。DOメモリだけに認可世代を置く案は、再起動や分断後の根拠を失うため採らない。別テーブルも可能だが、状態と二つの世代を同じrowで更新する方が、現在のNode単位の失効を一つのSQLで確定できる。

1からの移行値は過去の権限を証明しない。通常のアプリ操作以外によるDB改ざん、古いバックアップの全面復元、旧バイナリとの混在書込を防ぐ信頼根でもない。署名付きpolicyと割当世代の永続化・Node側での確認は別に必要となる。

## 互換性・復旧・見直し条件

既存のNode JWT、CredentialResponse、GET /agent/identity、WSS v1は変更しない。認可世代を未署名のAPI値としてNodeへ渡してpolicyの代用にする経路も追加しない。

追加列を消す自動rollbackは設けない。将来v2を有効にする際は、この列を更新しない旧Workerとの混在を禁止する。バイナリを戻す前にPermit/policyの発行と実行を停止し、保存済み世代・失効状態を維持して確認する手順が必要となる。本番DBへの移行や復旧は今回実施しない。

署名付きpolicyの形式・配信・確定保存、鍵やRoleの再登録、オフライン許可の上限、時計の信頼源、Node IDと世代の復旧方式を実装する前に見直す。分断中の即時失効と物理exactly-onceは保証しない。詳細な試験と残作業は[実装記録](../../node-authorization-epoch.md)に示す。
