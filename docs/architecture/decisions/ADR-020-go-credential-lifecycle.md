# ADR-020 Goの期限前更新とWSSの調停

Phase 01のローカル検証向けに採用する。[ADR-019](ADR-019-go-node-provisioning.md)の結果不明・再参加の境界は維持する。本番の鍵保管方式は確定しない。

## 理由と決定

手動rotateだけでは、接続中のClientが古い資格を保持する。Lifecycleが同じoriginのProvisioner、WSS、端末識別、命令履歴をまとめて扱い、旧接続と受信goroutineを回収した後で一度だけ資格を更新する。成功した新資格でClientを作り直し、保存済み接続世代から再開する。

更新は既定で期限30秒前とする。正常な更新は終了要求まで継続する。通信障害の再接続は既存Runnerの有限枠を使い、正常更新後も消費済みの失敗回数と指数backoffの幅を引き継ぐ。予定した更新をAgent全体の停止と表示しない。

Contextの予定中断だけを更新へ変換する。Context以外の接続解放失敗、認証拒否、署名・契約違反を含む場合は停止する。rotateの待機も旧資格の期限で打ち切る。更新応答が失われた場合は結果不明として停止し、自動再送・自動再参加をしない。世代が一つ進み、期限も延び、次の更新時刻が未来になることを確認する。条件を満たさない資格で即時更新を繰り返さない。

接続解放失敗にはRunnerからErrSessionCloseを付け、更新の予定時刻に関係なく再試行せず停止する。解放を確認できない接続を残して新しい接続を増やさないためである。正常解放後の通信断は従来どおり有限のbackoffへ進む。

## 代替案とトレードオフ

接続を残したまま先に更新する案は、旧接続の失効とACK・履歴処理が競合するため採用しない。予定更新でも総接続回数を消費する案は、正常運転が数回の更新で終了するため採用しない。逆に更新ごとに障害枠を戻すと断続的な障害で再試行が続くため、失敗回数はRun全体で保持する。

接続を閉じて更新する方式では制御に短い空白が生じる。確定予約のローカル実行と、資格世代をまたぐ未ACK命令の扱いは別に検証する。正常更新が動いても、実録画・無期限の分断耐性・本番運用の完了とは扱わない。

## 試験と見直し条件

NODE-02のloopback TLS相互試験では、資格の寿命を変更せず更新時刻を期限290秒前へ早め、約10秒で旧接続終了・更新・新世代のWSS・予約台帳・失効後停止を確認する。この試験を、既定間隔や長時間運転の実測として報告しない。

本番へ進む前に、永続的な鍵・資格・確認世代、再起動後の復旧、時刻ずれ、適切な更新余裕、制御の空白、実EncodeNodeの接続を確認する。再試行枠の回復ポリシーと長時間の運転方法も、障害注入の結果に基づいて再検討する。
