# ADR-019 Goの参加・資格更新と結果不明からの復旧

Phase 01のローカル検証向けに採用する。本番の鍵保管・配布方式は未決定のまま維持する。

## 理由と決定

既存のjoinは一回限りの参加コードを消費し、rotateは現在の資格世代を進める。変更後に応答が失われると、旧資格と同じ要求の再送では新資格を取得できない。通信失敗を未実行と推定しない。

GoのProvisionerは固定したHTTPS originのjoin/rotateだけを呼び、端末証明を操作とchallengeへ拘束する。Browser資格、Cookie、Origin、リダイレクト、Proxy環境変数を使用しない。資格応答もJSON Schema、サイズ、署名、家庭・環境・役割、期限、世代を検査する。

更新を送信する直前にProvisionerから現在資格を返す処理を止める。送信開始後の通信障害、HTTPエラー、不正応答、中断は結果不明として保持し、rotateを自動再送しない。復旧には管理者が既存のchallenge APIで新しい参加コードを発行し、同じ登録端末鍵でjoinする。復旧時も最後に確認した世代より新しい資格だけを受け付ける。joinも自動再送しない。

キーと資格はメモリ内だけで扱い、ログや命令履歴へ保存しない。再起動後の永続的な世代の照合と鍵保管は未実装であり、ここで本番の資格保管方式を決めない。失効したNodeは管理者のchallenge発行から拒否され、この復旧経路で失効を解除できない。

## 代替案とトレードオフ

サーバーへ操作ID付きの冪等な再発行APIを設ける案は、暗号化した応答の保持、資格の再取得権限、保存期間の設計が必要になるため今回は採用しない。新しい管理者操作を要求する方式は自動復旧の利便性を下げるが、既存の一回限りの権利と失効境界を維持できる。

応答エラーでも旧資格を使い続ける案は、既に失効している可能性を隠すため採用しない。送信開始前の入力不正と中断では要求を送らず、現在資格を保持する。

## 試験と見直し条件

NODE-01/SEC-02でGoからWorkerのjoin/rotateと更新後のWSSを確認する。GoのTLS fixtureでは応答喪失、不正な署名・世代・家庭、サイズ、リダイレクト、同時更新、中断、再参加を試験する。実環境WSS、本番資格、電源断後の復旧、EncodeNodeの実Agentは別途検証を要する。

無人運用、長期常駐、再起動をまたぐ資格更新へ進む前に、鍵保管、永続的な世代管理、期限前更新の調停、結果不明からの復旧権限を再検討する。
