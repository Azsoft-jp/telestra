# 06 / UI・PWA・使いやすさ

## UX原則

利用者に「チューナーID」「S3バケット名」「Encoder profile ID」を通常操作で見せない。画面は「見る」「録る」「録画を見る」「端末に保存する」の4つを中心に設計する。高機能設定は管理画面へ分離する。

## IA / 画面

| 画面 | 主操作 | 重要な状態 |
| --- | --- | --- |
| ホーム | 今放送中、録画予定、続きから見る | 受信不可、予約失敗、未接続 |
| 番組表 | チャンネル・日付選択、番組詳細、予約 | 取得中、最終更新、変更、競合 |
| ライブTV | 視聴、画質、字幕、音声、追っかけ | 接続、変換待ち、再接続、buffering |
| 録画ライブラリ | 検索、再生、保存、削除 | 録画中、転送中、変換中、未完了 |
| オフライン | 端末保存、容量、再開、削除 | 保存済み、再開可、端末容量不足 |
| 管理 > ノード | 追加、接続確認、能力、警告 | online/degraded/offline/credential expired |
| 管理 > ストレージ | Primary/Secondary、容量、検証 | replica lag、容量枯渇 |
| 管理 > 監査/設定 | 予約優先度、通知、権限 | 操作履歴、DR状態 |

## 初回導入フロー（最大4ステップ目標）

1. ログインし、家庭/環境名を設定。
2. 画面の指示に従いTunerNodeをインストールし、短命ペアリングコードで登録。
3. 検出したMirakurun/mirakcとチャンネルを確認し、EPGの初回同期を待つ。
4. 推奨の保存先・録画品質で開始。高度設定と第二EncodeNodeは後から追加可能。

失敗メッセージ例:

- 「EPGを更新できませんでした。前回の番組表を表示しています（最終更新 19:02）」
- 「録画は続いています。映像の変換ができるノードを待っています」
- 「端末の空き容量が不足しています。保存先を変えるか、録画画質を下げてください」
- 「録画停止を依頼しました。チューナーの応答待ちです」

## SAP Fundamental Styles

- ベース: SAP Fundamental Stylesの最新対応版をversion pin（実装着手時に公式変更履歴確認）。
- デザイン: Fiori系の明快な情報構造、角丸なし、線/余白/階層とアクセントで判別。
- `--app-radius: 0`から各ボタン・入力・カード・Dialogへのトークン/SCSS層の上書きを設計。CSS全体に`* { border-radius:0!important }`をかけない。カレンダー、フォーカス、tooltipの機能破壊を防ぐ。
- 文字サイズ/行間、focus visible、タッチターゲット、コントラスト、拡大200%、prefers-reduced-motion。
- Yomiyasuがユーザー指定の日本語推敲ルールだと仮定。現在パッケージに外部skillは同梱せず、文意・主語・文末・用語を自然な日本語で校閲する。ライセンスと導入方法は運用者が確認。

## レスポンシブ

| 幅 | EPG | ナビ |
| --- | --- | --- |
| 大画面 | チャンネル×時間の多列グリッド、詳細ペイン | 左ナビ＋上部検索 |
| タブレット | 絞ったチャンネル列、横スクロール、Dialog | 省スペース |
| スマホ | 今/次/検索の縦リストを既定、任意で横タイムライン | 下部4タブ |
| TV/リモコン | フォーカス可視化、方向キー、十字移動と決定 | 大きい操作域 |

EPG表は単なる`div`の集合ではなく、スクリーンリーダー向けの現在位置・日時・番組名を提示。仮想化してもキーボード移動とフォーカスを維持し、代替の線形リストビューを提供する。

## PWA

- Installable manifest、Service Workerによるアプリシェルのオフライン表示。
- サーバーメタデータの最小スナップショットをIndexedDBへ保存。ユーザー操作で更新・削除可。
- PWA内部録画保存: OPFS/ブラウザ保存領域のfeature detect→空き容量確認→前景chunk DL→length/hash検証→atomic commit相当→オフラインライブラリ登録。
- 中断/再開はchunk完了位置から。`Range`可否とETag/hash一致を確認し、変更された元データに古いchunkを混在させない。
- Background Fetch/Background Syncは機能検出された端末での加点機能に過ぎず、完走を保証しない。
- ユーザーに保存方法を選択させる: 「アプリ内に保存」 / 「ファイルを書き出す」。書き出し形式はMP4+字幕sidecar等の互換性と情報損失を表示。
- 完全オフライン時は保存済み映像+字幕描画器+必要な字幕データ+音声トラックで再生できることをテスト。
- OSは容量を制限・保存データを削除し得る。PWAのデータは唯一のバックアップにしない。
- 著作権/権限のあるコンテンツだけをテスト・配信する。

## 予備フロントのUX

Primaryで問題が起きたときに、外部のブックマーク/管理ドキュメント/独立した通知経路から`backup.example.net`のような予備URLを案内。

- 別originではログインし直し、PWAを別アプリとして認識する。
- 予備URLにPrimaryで保存したOPFS/IndexedDBのデータは現れない。
- API/認証が停止していれば予備画面で`現在は番組表・録画予約を利用できません`と明示。フロント故障とBackend故障を取り違えない。
- Cloudflare障害時にCloudflare経由のリダイレクトやWorkerで予備URLを案内する方式だけに依存しない。
