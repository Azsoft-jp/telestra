# 困ったとき

まず実行したコマンド、OS・Node.js・Goの版、成功した検査、最初に失敗した工程を記録する。Token、鍵、実IP、宅内ホスト名、実番組履歴、未伏字ログをIssueへ貼らない。

| 症状 | 確認と対処 |
| --- | --- |
| npm ciが失敗 | リポジトリのルートとNode.js 24を確認。lockfileを勝手に削除しない。初回は通信が必要 |
| Goの依存物がない | go mod downloadを実行。試験中はGOPROXY=offのため自動取得しない |
| Demoを開けない | 起動ログの127.0.0.1のURLを使用。終了していないか、ポートが別プロセスに使われていないか確認 |
| ポートを使えない | telestra demo --port 5174で変更。--hostや外部公開の指定は提供しない |
| 原本結果が取得できない | Goの有無と起動ターミナルを確認。Demoを再起動し、結果を再読込 |
| 映像が再生できない | 現在は仕様どおり。合成fixtureは実Codecの映像ではなく、playable:false |
| NOT_IMPLEMENTED | 外部Storage、staging/production、live、PWA、dual-staticをMockへ渡していないか確認 |
| WSSの資格・形式で停止 | 資格の用途、家庭・環境・世代、期限、登録鍵をローカルfixtureで照合。無限再接続や署名検証の省略で回避しない |
| 履歴が破損・結果不明 | 空へ初期化しない。再実行せず保存済み状況を照合。自動復旧は未実装 |
| テストが45秒ほど待つ | DO alarmの実時間試験がある。終了コードを確認するまで合格とは扱わない |
| Dockerが動かない | Compose導入は未提供。ホスト上のDemo手順を使用する |

Mockを再起動すると合成結果を再作成する。実録画の復元を意味しない。ローカルで変更したコードは上書きせず、差分を保管してから更新する。削除は[導入ガイド](installation.md)を参照する。

秘密の漏えいが疑われる場合は、公開Issueへ詳細を貼らず[SECURITY.md](../SECURITY.md)へ進む。失効・ローテーションと履歴の処置を別々に記録し、履歴を消しただけで安全になったとは判断しない。
