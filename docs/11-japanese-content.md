# 11 / 日本語UI文言ガイド

Yomiyasuを想定した自然な日本語のレビュー方針。外部Skill本体は配布しない。利用者がYomiyasuを導入している場合はその手順を優先し、未導入でも以下の基準で校閲する。

## 用語集

| 内部用語 | 利用者向け表記 | 注意 |
| --- | --- | --- |
| Recording intent | 録画予約 | 実際に録れた保証ではない |
| Recording active | 録画中 | 受信中とアップロード完了を分ける |
| Upload pending | 転送待ち | ローカルにはまだデータがある |
| Encoding queued | 変換待ち | `録画できません`と誤表現しない |
| Offline package | アプリ内に保存 | OSのファイル一覧にあるとは限らない |
| File export | ファイルを書き出す | 外部プレイヤー互換情報を明示 |
| Agent offline | チューナーと通信できません | 予約継続中の可能性を分ける |
| Cancel pending | 録画停止を確認中 | 送信だけで「停止済み」としない |
| Degraded EPG | 前回の番組表を表示中 | 最終取得日時が必須 |
| Standby frontend | 予備サイト | APIが復旧していない場合は別表示 |

## レビュー原則

1. 一文の主語・動作・結果を分かる形にし、名詞の連続を減らす。
2. 状態・原因・次にできることを短く示す。「失敗しました」だけで終えない。
3. 専門用語は管理画面に限定し、通常画面では利用者が理解できる名称を使う。
4. ボタンラベルは動詞。`録画する`、`保存する`、`再試行`など。
5. `成功`,`確定`,`完了`は永続化・ACK等の定義に沿う。単にAPIで受理された状態を`録画完了`としない。
6. 謝罪や冗長な敬語を繰り返さず、警告の重大度と文体を統一する。
7. 色だけに頼らずアイコン/文言/ARIA live regionで状態を伝える。
8. 日時は日本の利用者向けに`10月29日 19:30`等。内部のUTCと混同しない。

## マイクロコピー例

| 状態 | 推奨 |
| --- | --- |
| ネットワーク切断中 | 「接続が切れています。録画はチューナー側で続いている場合があります。」 |
| 原本保存済・変換待ち | 「録画は保存済みです。再生用の映像を準備しています。」 |
| スプール逼迫 | 「録画の一時保存領域が残り少なくなっています。転送先と回線を確認してください。」 |
| PWA容量不足 | 「この端末には保存できません。容量を空けるか、ファイルとして書き出してください。」 |
| 予備フロント/API失敗 | 「予備サイトは開けましたが、番組情報を取得できません。」 |
| EPG更新失敗 | 「番組表を更新できませんでした。前回取得した情報を表示しています。」 |

## UIレビュー手順

- `prompts/JAPANESE_COPY_REVIEW.md`を使い、作業範囲の全ラベル、エラー、Toast、通知、ARIAテキストをレビュー。
- 低年齢層・高齢者を含め、操作の意味が伝わるか簡易ユーザーテストを実施。
- Yomiyasu本体をインストール/実行していない場合は、校閲済みと誤記載せず「独自ガイドによるレビュー」と区別。
